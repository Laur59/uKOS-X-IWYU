# uKOS-X Pack v. 3.x.x

NOTE: Throughout the documentation, the term *`PATH_UKOS_X_PACKAGE`* is used to refer to the location where uKOS-X is located (typically git clone destination).

## Prerequisites

The installation of **µKOS-X** requires a set of development tools. Before proceeding, ensure that the following components are available on your system.

- cmake
- toolchain for Arm processors with newlib
- toolchain for RISC-V processors with newlib
- yq
- python3

## Preparing work environment

It is sufficient to initialise the paths where the toolchains are located.

```bash
PATH_GCC_ARM=Your_Path_To_The_gcc_arm
PATH_GCC_RVXX=Your_Path_To_The_gcc_riscv
PATH_LLVM_ARM=Your_Path_To_The_llvm_arm
PATH_LLVM_RVXX=Your_Path_To_The_llvm_riscv

export PATH_GCC_ARM
export PATH_GCC_RVXX
export PATH_LLVM_ARM
export PATH_LLVM_RVXX
```

The default C library is **newlib**; **picolibc** and **llvmlibc** (LLVM libc) are
also supported and select their own toolchains. Set these additional paths only
if you intend to build with them:

```bash
PATH_LLVM_ARMP=Your_Path_To_The_llvm_arm_picolibc   # for -DC_LIBRARY=picolibc (LLVM)
PATH_GCC_ARMP=Your_Path_To_The_gcc_arm_picolibc     # for -DC_LIBRARY=picolibc (GCC)
PATH_LLVM_ARML=Your_Path_To_The_llvm_arm_llvmlibc   # for -DC_LIBRARY=llvmlibc (LLVM, ARM only)

export PATH_LLVM_ARMP
export PATH_GCC_ARMP
export PATH_LLVM_ARML
```

See **LLVMLIBC_TOOLCHAIN_GUIDE.md** for details on building with LLVM libc.

## Building the package

Once the installation is terminated, we can build all the targets and start to work with the OS. Run the following commands from  *`PATH_UKOS_X_PACKAGE`* directory.

### Building TinyUSB

```bash
cd Third_Parties/TinyUSB
cmake -S . -B build
cmake --build build
```

### Building MicroPython

```bash
cd Third_Parties/MicroPython
cmake -S . -B build
cmake --build build
```

### Building FatFs

```bash
cd Third_Parties/FatFs
cmake -S . -B build
cmake --build build
```

### Building esp32

```bash
cd ${PATH_UKOS_X_PACKAGE}/Third_Parties/esp32
./build.sh
```

### Building esp32

```bash
cd ${PATH_UKOS_X_PACKAGE}/Third_Parties/esp32
./build.sh
```

### Building TFLite-micro

```bash
cd Third_Parties/Tflite-micro/Construction/Pyenv
python3.13 -m venv Tflite_Pyenv
source Tflite_Pyenv/bin/activate

pip install -r requirements.txt

deactivate
./build.sh
```

### Building decnumber

```bash
cd ${PATH_UKOS_X_PACKAGE}/Third_Parties/decnumber
cmake -S . -B build
cmake --build build
```

### Building LVGL

```bash
cd ${PATH_UKOS_X_PACKAGE}/Third_Parties/LVGL
cmake -S . -B build
cmake --build build
```

### Building IntelRDFPMath

```bash
cd ${PATH_UKOS_X_PACKAGE}/IntelRDFPMath
cmake -S . -B build
cmake --build build
```

### Building all the targets of the package

```bash
cd PATH_UKOS_X_PACKAGE/Ports/Targets
._/build.sh
```

In the folder Targets you can read the document **README.md** for more information.

### Possible operations with one target

For building one specific target we simply need to enter in the **Variant__** folder of the target and play with **cmake**. For example, if we need to **build** and **burn** the **FLASH** of the target **Nucleo_H743**.

```bash
cd PATH_UKOS_X_PACKAGE/Ports/Nucleo_H743/Variant_Test
cmake --preset gcc
cmake --build build --target burn
```

CMake offers the following presets:

- gcc
- llvm
- gcc-nocanary, suppress detection if a buffer overflow in stack
- gcc-nouser, compile the system without the privileged/user separation
- gcc-nouser-nocanary
- llvm-nocanary, suppress detection if a buffer overflow in stack
- llvm-nouser, compile the system without the privileged/user separation
- llvm-nouser-nocanary

#### Working with the target

1. Connect a serial terminal (e.g. CoolTerm) set with the baudrate **460800-b/s**

2. Push reset. On the terminal the OS prompt should appear
